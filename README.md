# TalentMap AI

Навигатор развития талантов для детей 6–18 лет. Диагностика интересов за 12 вопросов, персональная карта «Созвездие компетенций», подбор офлайн-кружков, онлайн-курсов и ИТ-инструментов под каждый навык, портфолио работ и геймификация.

**Стек:** Node.js + Express + SQLite (бэкенд) · React 19 + Vite + Tailwind CSS 4 (фронтенд)

---

## Быстрый старт

```bash
# 1. Зависимости (сервер + клиент)
npm run setup

# 2. Конфигурация
cp .env.example .env

# 3. Сборка фронтенда
npm run build

# 4. Запуск
npm start
```

Откройте **http://localhost:3000**

При первом запуске база создаётся и наполняется автоматически: 14 созвездий, 70 навыков, 210 обучающих ресурсов, 45 городов, 7 товаров магазина и два аккаунта.

1. **Лендинг** — презентация продукта, FAQ, призыв к действию

## Как это работает

### Подбор направлений без ИИ

Диагностика **не требует API-ключа**. Каждый вариант ответа несёт веса по тринадцати признакам (`art`, `logic`, `hands`, `precision`, `digital` и т. д.). Профиль ребёнка складывается из ответов, затем считается косинусная близость с профилем каждого созвездия, применяются возрастные ограничения и поправка на боязнь сложных программ. На выходе — 2–4 направления с объяснением, почему они подобраны.

Если задать `AI_API_KEY`, подключается любой OpenAI-совместимый провайдер (Groq, OpenAI, OpenRouter, локальный сервер). ИИ при этом **не** заменяет расчёт — он только формулирует текст рекомендации, отвечает в чате наставника и комментирует работы в портфолио. При ошибке или таймауте всё автоматически возвращается в офлайн-режим.

### Логика карты

Навык доступен, когда пройдены все его предшественники **внутри видимой части графа**. Ровно одна звезда помечается текущей: сначала берётся созвездие с наибольшим прогрессом, внутри него — навык с наименьшим порядковым номером. Сервер проверяет доступность при каждой отметке, поэтому пройти навык в обход последовательности нельзя. Админ-панель отклоняет связи, образующие цикл, — иначе целая ветка навыков заблокировалась бы навсегда.

### Безопасность

- Личность запроса берётся **только из JWT**. Поле `userId` в теле запроса игнорируется везде.
- Весь `/api/admin/*` закрыт ролью администратора.
- В продакшене сервер не стартует без `JWT_SECRET` длиной от 32 символов.
- Пароли и родительский PIN хранятся как bcrypt-хеши.
- Цены в магазине берутся из БД, а не из запроса.
- Лимит бесплатного тарифа проверяется на сервере.
- Ограничение частоты запросов: 10 попыток входа за 15 минут, 20 сообщений ИИ в минуту.
- `helmet` с политикой CSP, CORS по списку разрешённых origin, валидация всех входных данных через Zod.
- Загружаемые файлы: белый список MIME-типов, лимит 5 МБ, случайные имена на диске.

## Переменные окружения

Полный список с пояснениями — в [`.env.example`](.env.example). Минимум для продакшена:

```bash
NODE_ENV=production
JWT_SECRET=<48 случайных байт в hex>
CORS_ORIGINS=https://ваш-домен
ADMIN_PASSWORD=<надёжный пароль>
```

Сгенерировать секрет:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

## Развёртывание

Приложение самодостаточно: один процесс Node отдаёт и API, и собранный фронтенд.

```bash
npm run setup
npm run build
NODE_ENV=production npm start
```

Что стоит вынести на постоянные тома: `data/` (база SQLite) и `uploads/` (работы из портфолио).

За обратным прокси (nginx, Caddy) сервер уже настроен на `trust proxy` — заголовок `X-Forwarded-For` учитывается при ограничении частоты запросов.
