# TalentMap AI

Навигатор развития талантов для детей 3–18 лет. Диагностика интересов за 12 вопросов, персональная карта «Созвездие компетенций», подбор офлайн-кружков, онлайн-курсов и ИТ-инструментов под каждый навык, портфолио работ и геймификация.

**Стек:** Node.js + Express + SQLite (бэкенд) · React 19 + Vite + Tailwind CSS 4 (фронтенд)

---

## Быстрый старт

```bash
# 1. Зависимости (сервер + клиент)
npm run setup

# 2. Конфигурация
cp .env.example .env

# 3. Сборка фронтенда
npm run build

# 4. Запуск
npm start
```

Откройте **http://localhost:3000**

При первом запуске база создаётся и наполняется автоматически: 14 созвездий, 70 навыков, 210 обучающих ресурсов, 45 городов, 7 товаров магазина и два аккаунта.

## Что внутри

### Пользовательский путь

1. **Лендинг** — презентация продукта, FAQ, призыв к действию
2. **Регистрация** — только имя, email и пароль
3. **Онбординг** — выбор роли (родитель / подросток 12+) и приветствие из трёх шагов
4. **Диагностика** — 12 вопросов по одному на экран: 7 о ребёнке и 5 игровых. От 4 до 8 вариантов в вопросе, на трёх вопросах можно выбрать несколько ответов. Формулировки зависят от роли: подростку, который проходит тест сам, всё задаётся на «ты»
5. **Результат диагностики** — процент совпадения по каждому направлению, разбор сильных сторон и честная отметка о точности подбора
6. **Карта созвездий** — главный экран: звёзды-навыки, связи, четыре состояния, модальное окно с тремя типами ресурсов
7. **Портфолио** — загрузка работ перетаскиванием, фильтр по компетенциям, отзыв ИИ
8. **Магазин** — трата XP на аватары, рамки и звания, которые видны во всём приложении
9. **Профиль** — круговая диаграмма прогресса, история действий, подписка
10. **Родительский раздел** — аналитика под PIN-кодом
11. **Админ-панель** — редактор графа навыков, ресурсы, справочник городов, список пользователей

## Как это работает

### Как считается оценка

Диагностика **не требует API-ключа**. Каждый вариант ответа несёт веса по пятнадцати признакам интересов (`art`, `logic`, `hands`, `precision`, `digital`, `words`, `nature` и др.). Профиль ребёнка складывается из ответов, затем считается косинусная близость с профилем каждого направления.

Что делает оценку осмысленной:

- **вклад вопроса нормируется** по числу выбранных вариантов — иначе вопрос с множественным выбором перевешивал бы обычный просто потому, что там отметили два пункта;
- **возрастной штраф растёт быстрее линейного**: год-два разницы почти не мешают (семилетке можно дать введение в программирование), а разрыв в пять лет решает — кибербезопасность семилетке не предложат;
- **близость переводится в процент** через кривую, растягивающую середину шкалы, иначе все направления скучивались бы в диапазоне 40–70 %;
- **точность подбора оценивается честно**: если отрыв лидера мал, ответов мало или подошло меньше двух направлений, результат помечается как предварительный;
- **слабые совпадения не показываются процентом** — вместо «совпадение 0 %» направление помечается как «для знакомства».

На выходе — 2–4 направления с процентом совпадения и объяснением, плюс разбор сильных сторон ребёнка.

### Как проверяется, что подбор осмысленный

Сквозной тест проверяет механику: кнопки нажимаются, экраны сменяются. Этого мало — прототип «работал» и при этом выдавал всем одну и ту же карту.

`tests/profiles.mjs` проходит диагностику пятью непохожими профилями (художник 8 лет, инженер 12, блогер 15, натуралист 13, программист 16) и требует, чтобы:

- каждый попал в ожидаемую область (натуралист — в биоинженерию, инженер — в робототехнику или инженерную графику);
- восьмилетнему художнику не предлагали кибербезопасность и работу с данными;
- ни у кого не было нулевого совпадения, а лидер набирал хотя бы 55 %;
- **все пять наборов рекомендаций отличались друг от друга.**

### Валидация ответов

Набор вопросов (`src/services/questions.js`) — единственный источник правды и для формы, и для проверки. Сервер отклоняет несуществующий вопрос, выдуманный вариант ответа, массив там, где разрешён один выбор, превышение лимита множественного выбора, совмещение взаимоисключающего варианта с остальными и попытку построить карту меньше чем по трём содержательным ответам.

Если задать `AI_API_KEY`, подключается любой OpenAI-совместимый провайдер (Groq, OpenAI, OpenRouter, локальный сервер). ИИ при этом **не** заменяет расчёт — он только формулирует текст рекомендации, отвечает в чате наставника и комментирует работы в портфолио. При ошибке или таймауте всё автоматически возвращается в офлайн-режим.

### Логика карты

Навык доступен, когда пройдены все его предшественники **внутри видимой части графа**. Ровно одна звезда помечается текущей: сначала берётся созвездие с наибольшим прогрессом, внутри него — навык с наименьшим порядковым номером. Сервер проверяет доступность при каждой отметке, поэтому пройти навык в обход последовательности нельзя. Админ-панель отклоняет связи, образующие цикл, — иначе целая ветка навыков заблокировалась бы навсегда.

### Ничего не спрашивается дважды

Каждая сущность собирается ровно в одном месте: имя, почта и пароль — при регистрации, роль — на онбординге (ТЗ 3.1), возраст и город — среди двенадцати вопросов диагностики (ТЗ 3.2). Сквозной тест проверяет это отдельной проверкой, чтобы дубли не вернулись при доработках.

Роль сохраняется в профиле, а не в состоянии навигации, и определяет формулировки: родителю — «Сколько лет ребёнку?», подростку — «Сколько тебе лет?».

Администратор видит в меню подписанный пункт «Админ-панель»; на экране входа есть кнопка быстрого входа под администратором.

### Безопасность

- Личность запроса берётся **только из JWT**. Поле `userId` в теле запроса игнорируется везде.
- Весь `/api/admin/*` закрыт ролью администратора.
- В продакшене сервер не стартует без `JWT_SECRET` длиной от 32 символов.
- Пароли и родительский PIN хранятся как bcrypt-хеши.
- Цены в магазине берутся из БД, а не из запроса.
- Лимит бесплатного тарифа проверяется на сервере.
- Ограничение частоты запросов: 10 попыток входа за 15 минут, 20 сообщений ИИ в минуту.
- `helmet` с политикой CSP, CORS по списку разрешённых origin, валидация всех входных данных через Zod.
- Загружаемые файлы: белый список MIME-типов, лимит 5 МБ, случайные имена на диске.

## Демоверсия на GitHub Pages

В репозитории настроена публикация бесплатного демо: при каждом пуше в `main` GitHub Actions собирает статическую версию и выкладывает её на Pages.

GitHub Pages отдаёт только файлы — ни Node, ни SQLite там не запустить. Поэтому в демо-сборке API заменён реализацией, работающей прямо в браузере (`client/src/demo`), а данные пользователя хранятся в его localStorage.

Ключевой момент: **демо не пишется вручную и не расходится с продуктом.** Скрипт `scripts/build-demo-data.js` запускает настоящий сидер, выгружает получившиеся таблицы в снимок и транспилирует общие модули логики из CommonJS в ESM. Подбор направлений в демо считает тот же код, что и сервер.

```bash
npm run demo:data    # выгрузить снимок и сгенерировать ESM-модули
npm run demo:build   # то же + собрать демо-бандл
```

Ограничения демо, о которых честно сообщает баннер в интерфейсе:

- данные видны только в том браузере, где их создали;
- редактирование карты в админ-панели отключено;
- очистка данных сайта сбрасывает всё к начальному состоянию.

Обычная сборка демо-код не содержит: `vite.config.js` подменяет модуль `@demo` заглушкой, поэтому снимок данных не попадает в продакшен-бандл.

## Развёртывание

Приложение самодостаточно: один процесс Node отдаёт и API, и собранный фронтенд.

```bash
npm run setup
npm run build
NODE_ENV=production npm start
```

Что стоит вынести на постоянные тома: `data/` (база SQLite) и `uploads/` (работы из портфолио).

За обратным прокси (nginx, Caddy) сервер уже настроен на `trust proxy` — заголовок `X-Forwarded-For` учитывается при ограничении частоты запросов.
