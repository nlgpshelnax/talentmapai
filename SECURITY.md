# Безопасность TalentMap AI

Документ описывает, от чего защищено приложение, чем именно, и что обязан
настроить владелец на стороне хостинга. Разделы намеренно написаны так, чтобы
их можно было показать заказчику: без жаргона там, где он не нужен, и без
обещаний того, чего код сделать не может.

Проверка: `npm run test:security` — 27 проверок, каждая пытается провести
настоящую атаку.

---

## Что защищаем

Продукт для детей 6–18 лет. В базе лежат имя, возраст, город, работы ребёнка и
его переписка с наставником. Утечка здесь — это не «утекли адреса почты», это
персональные данные несовершеннолетних. Отсюда все решения ниже.

Отдельная особенность: **родитель и ребёнок делят один аккаунт**. Раздел
аналитики закрыт PIN-кодом не от постороннего, а от самого ребёнка — поэтому
подбор PIN блокируется так же строго, как подбор пароля.

---

## Кто вход, тот и есть

Личность берётся **только из подписанного токена**. Ни один обработчик не
читает идентификатор пользователя из тела или строки запроса.

| Мера | Зачем |
|---|---|
| Алгоритм подписи задан явно (`HS256`) | Иначе токен сам сообщает, каким алгоритмом его проверять. Токен с `alg: none` не имеет подписи вовсе и был бы принят |
| Поколение токена (`token_version`) | Смена пароля обрывает **все** ранее выданные сессии. Без этого угнанный доступ переживал смену пароля и жил до конца срока |
| Пользователь читается из базы на каждом запросе | Снятые права администратора действуют немедленно, а не через трое суток |
| Секрет обязателен на боевом сервере | Приложение не стартует без `JWT_SECRET` длиной от 32 символов. Предсказуемый секрет — это возможность подписать себе любой токен |

Токен хранится в `localStorage`. Это осознанный выбор: альтернатива —
куки, а они приносят подделку межсайтовых запросов и требуют отдельной защиты.
При запрете inline-скриптов в политике источников контента (см. ниже) риск
кражи токена через внедрённый скрипт закрыт на входе.

## Пароли и подбор

| Мера | Значение |
|---|---|
| Хеширование | bcrypt, 12 раундов |
| Одинаковый ответ на несуществующую почту и неверный пароль | Иначе перебором почт узнают, кто зарегистрирован |
| Постоянное время сравнения | Сравнение выполняется всегда, даже когда аккаунта нет — иначе время ответа выдаёт существование ящика |
| Блокировка по цели атаки | 8 неудач за 15 минут → блокировка на 15 минут |
| Счётчик в базе, а не в памяти | Перезапуск сервера не обнуляет его; несколько копий приложения видят общий счётчик |
| Ключ нормализуется | `Ivan@` и `ivan@` — одна цель. Иначе смена регистра обнуляет счётчик |

**Почему блокировка привязана к почте, а не к адресу.** Ограничение по адресу
обходится ботнетом или подменой заголовка прокси. Подбор пароля от конкретного
ящика так не ускорить: счётчик у цели один, откуда бы ни пришёл запрос.

Родительский PIN — четыре цифры, десять тысяч комбинаций. Без блокировки
скрипт перебирает их за минуты. Счётчик тот же, привязан к аккаунту, действует
и на проверку, и на смену, и на снятие кода.

## Защита от перегрузки

Граница возможного, честно: **объёмную атаку в сотни гигабит приложением на
Node не отбить**. Трафик умрёт на канале раньше, чем дойдёт до процесса. Для
этого нужен внешний рубеж — см. раздел «Что настроить на хостинге».

В коде закрыто то, что действительно решается в коде: прикладная атака одним
ноутбуком.

### Подделка адреса клиента

Раньше стояло безусловное доверие заголовкам прокси. Это означало, что любой
клиент присылает в `X-Forwarded-For` выдуманный адрес и получает чистый
счётчик ограничений на каждый запрос — то есть защиты не было вовсе.

Теперь доверие включается явно через `TRUST_PROXY` и **по умолчанию
выключено**. Ставьте его, только если перед приложением действительно стоит
обратный прокси.

### Ограничения по классам маршрутов

Раньше на весь API стоял один потолок: проверка живости и обращение к языковой
модели стоили одинаково. Теперь по стоимости запроса:

| Класс | Потолок | Окно |
|---|---|---|
| Вход и регистрация | 10 | 15 мин |
| Родительский PIN | 8 | 10 мин |
| Загрузка файлов | 12 | 1 мин |
| Запись в базу | 60 | 1 мин |
| Чтение каталога | 240 | 1 мин |
| Администрирование | 90 | 1 мин |
| Общий потолок | 300 | 1 мин |

Считается по аккаунту у вошедших и по адресу у остальных. Для IPv6 берётся
подсеть `/56`: провайдер выдаёт клиенту целый блок, и перебор адресов внутри
него ничего не стоит.

### Плавное замедление

Жёсткий отказ сообщает атакующему точную границу, и он подстраивает темп.
Задержка перед ответом растёт с числом запросов и делает перебор бессмысленным
по времени, почти не мешая человеку, случайно нажавшему кнопку трижды.

### Медленные соединения

Классическая атака одним ноутбуком: открыть несколько сотен сокетов и отдавать
заголовки по байту. Соединения не закрываются, пул исчерпан, сервер молчит —
при почти нулевом трафике.

**Важное наблюдение:** встроенного `server.headersTimeout` для этого
недостаточно. В проверке соединение, куда подкидывали по заголовку каждые три
секунды, жило неограниченно долго. Поэтому срок считается своим сторожем и
**от момента открытия соединения**, а не от простоя: подкидывание байтов его не
сбрасывает. Проверено — соединение разрывается ровно по сроку.

### Сброс нагрузки

Потолок одновременной обработки. Под наплывом сервер принимает всё подряд,
очередь растёт, и в какой-то момент он не отвечает никому — включая тех, кто
пришёл первым. Лишним честно отказываем с кодом 503: те, кто уже внутри,
дождутся ответа.

Проверка живости из-под ограничения выведена — иначе оркестратор решит, что
приложение умерло, и перезапустит его в худший момент.

### Отсев сканеров

Любой сайт круглосуточно перебирают на предмет чужих движков: админка
WordPress, дампы баз, файлы окружения, каталоги `.git`. Раньше каждый такой
запрос отдавал страницу приложения весом в сотни килобайт. Теперь — короткий
отказ без разметки, до всех остальных обработчиков.

## Фильтрация входа

React экранирует вывод, поэтому классическое внедрение скрипта через
отображение закрыто самим фреймворком. Но это не вся картина: текст уходит
дальше — в письма, в отчёты на печать, в запрос к языковой модели, — а там
экранирования нет.

| Что чистим | Почему |
|---|---|
| Нормализация Unicode (NFC) | Два визуально одинаковых имени не должны быть двумя разными записями |
| Невидимые символы, нулевая ширина, BOM | Ими добивают строку, чтобы пролезть под ограничение длины |
| Переворот направления текста (bidi) | Позволяет отрисовать имя справа налево и визуально выдать себя за другого |
| Управляющие символы | Ломают вывод в журналы и отчёты |
| Разметка и сущности | Декодируем один раз и снимаем теги — чтобы `&lt;script&gt;` не ожил при следующем декодировании |
| Ведущие `=`, `+`, `-`, `@` | Внедрение формулы при выгрузке в таблицу |
| Стопка диакритики (Zalgo) | Отрисовочная атака, ломает вёрстку соседних строк |
| Длина в видимых символах | `👨‍👩‍👧‍👦` занимает 11 позиций в строке, но это один символ на экране |

**Проверка от перестраховки.** Фильтр не должен ломать нормальные данные:
`Анна-Мария`, `Пётр`, `Артём Ковалёв` проходят без изменений, а ребёнок,
написавший «хочу стать системным администратором», доходит до модели нетронутым.
Это отдельные тесты — они так же важны, как тесты на атаки.

### Ссылки

Администратор вводит ссылки на площадки и ресурсы, и они попадают в `href`.
React от `javascript:` в `href` **не защищает**. Разрешены только `http` и
`https`; отклоняются `javascript:`, `data:`, `vbscript:`, `file:`,
протокол-относительные `//чужой.сайт` и ссылки со встроенными учётными данными.

### Языковая модель

Текст ребёнка уходит в модель. Снимаются ролевые маркеры (`system:`,
`### Instruction`) и длинные ограждения кода, которыми переписывают системную
инструкцию. Фильтр намеренно осторожный: ложное срабатывание на живой детской
речи хуже, чем пропущенная попытка — системная инструкция и так не содержит
секретов.

## Загрузка файлов

Тип файла раньше брался из того, что прислал клиент. Это поле подделывается
одной строкой.

1. Ограничение размера — первый рубеж, на уровне приёма.
2. **Сигнатура файла**: реальный формат определяется по первым байтам
   (JPEG, PNG, GIF, WebP). Всё остальное отклоняется.
3. **Сверка** сигнатуры с заявленным типом и с расширением на диске. `.png` с
   байтами JPEG — в лучшем случае сломанный клиент, в худшем разведка.
4. **Размеры из заголовка** — без раскодирования пикселей: PNG IHDR, GIF LSD,
   обход маркеров JPEG, все три вида блоков WebP.
5. **Защита от картинки-бомбы**: потолок 10000 пикселей по стороне,
   50 мегапикселей по площади и предел отношения пикселей к весу файла. Файл в
   30 КБ, заявляющий 40 мегапикселей, — это бомба.
6. **Поиск встроенной начинки** в первых двух килобайтах: `<?php`, `<script`,
   `<!DOCTYPE html`, `<svg`. В настоящем растровом изображении такого не бывает.
7. Расширение на диске берётся из **распознанного** формата, а не из заявленного.
8. Отклонённая загрузка удаляется с диска. Сбой на любом последующем шаге —
   тоже: раньше неудачная запись в базу оставляла файл-сироту.

Отдача файлов: `Content-Disposition: inline`, `X-Content-Type-Options: nosniff`
и отдельная политика `default-src 'none'; sandbox`. Даже если что-то пройдёт все
проверки, браузер не станет исполнять это как страницу в контексте сайта.

## Заголовки ответа

| Заголовок | Значение |
|---|---|
| `Content-Security-Policy` | `script-src` без `unsafe-inline` — на этом держится вся защита от внедрения кода. `img-src` сужен со «всего https» до своего домена: адрес запроса за картинкой уносил на чужой сервер факт визита |
| `frame-ancestors 'none'` | Страницу нельзя накрыть прозрачным слоем в чужом фрейме и заставить ребёнка нажать не то, что он видит |
| `Strict-Transport-Security` | Полгода, с поддоменами. Браузер перестаёт даже пробовать `http` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `X-Content-Type-Options` | `nosniff` |
| `X-Powered-By` | Убран — версия сервера это разведданные |

Проверка живости на боевом сервере отвечает односложно. Окружение, режим ИИ и
время работы — тоже разведданные: по времени работы видно, когда последний раз
обновлялись, то есть какие уязвимости могли остаться незакрытыми.

## Запросы к базе

Все значения передаются параметрами. Четыре места собирают список изменяемых
колонок в строку — во всех именах колонок жёстко заданы в коде и не приходят
от пользователя. Миграции схемы дополнительно проверяют имена по образцу: не
потому, что сейчас есть риск, а чтобы он не появился, когда список однажды
начнут собирать из внешних данных.

Отдельная особенность SQLite: `LIKE` и `lower()` работают только с латиницей.
Поиск по кириллице вынесен в код — это исправление ошибки, но заодно снимает
целый класс проблем с построением условий.

## Секреты

| Переменная | На боевом сервере |
|---|---|
| `JWT_SECRET` | Обязательна, от 32 символов. Без неё приложение не стартует |
| `ADMIN_PASSWORD` | Обязательна. Без неё приложение не стартует |
| `ENABLE_DEMO_ACCOUNT` | Демо-аккаунт с общеизвестным паролем на боевом сервере **не создаётся**, если не включить явно |

При запуске выводятся предупреждения о слабой настройке: не задан список
разрешённых доменов, не настроена капча, включён демо-аккаунт. Запуск при этом
не блокируется — владелец мог сознательно поднять стенд.

Файл `.env` в репозиторий не попадает, в нём отслеживается только `.env.example`.

## Зависимости

`npm run audit` — проверка с осознанным списком исключений. Обычный `npm audit`
как ворота сборки бесполезен: он навсегда красный из-за одной неприменимой
находки, и его начинают игнорировать вместе с настоящими.

Правило: в исключения попадает только то, чего в сборке физически нет. У каждой
записи — обоснование, дата проверки и условие снятия.

Что было закрыто: 12 уязвимостей (одна критическая, девять высоких) в пакете
`tar` и в дереве `node-gyp`, которые приходили вместе с `sqlite3`. Закрыты
переопределением версий; ни `tar`, ни `node-gyp` не работают во время
выполнения — они нужны только при сборке нативного модуля из исходников.

Текущее исключение одно: `react-router`. Уязвимость в режиме React Server
Components, которого в сборке нет — приложение использует только классические
компоненты маршрутизации. Снимется с выходом версии 8.3.0.

## Что настроить на хостинге

Код закрывает прикладной уровень. Остальное — за внешним рубежом, и без него
защита неполна.

### Обязательно

1. **HTTPS.** Без него токен уходит по сети открытым текстом. Certbot или
   сертификат от прокси.
2. **Обратный прокси** (nginx, Caddy) или Cloudflare перед приложением.
   После этого выставить `TRUST_PROXY=1` — иначе ограничения будут считаться
   по адресу прокси, то есть по одному на всех.
3. **Переменные окружения**: `JWT_SECRET`, `ADMIN_PASSWORD`, `CORS_ORIGINS`.
   Без первых двух приложение не запустится.

### Настоятельно рекомендуется

4. **Cloudflare или аналог** — единственная реальная защита от объёмной атаки.
   Бесплатного тарифа достаточно: он поглощает трафик до вашего канала.
   Включить «Bot Fight Mode» и правило ограничения частоты на `/api/auth/*`.
5. **Капча** — `YANDEX_CAPTCHA_SECRET_KEY`. Без неё регистрация открыта для
   скриптов, и база наполнится мусорными аккаунтами.
6. **Ограничения на уровне nginx** как второй рубеж:
   ```nginx
   limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;
   limit_conn_zone $binary_remote_addr zone=conn:10m;

   location /api/ {
       limit_req zone=api burst=20 nodelay;
       limit_conn conn 20;
       client_body_timeout 10s;
       client_header_timeout 10s;
       client_max_body_size 6m;
   }
   ```
7. **Резервное копирование базы.** Один файл `data/talentmap.db` — скопировать
   по расписанию. Восстановление после сбоя важнее любой из мер выше.
8. **Обновления.** `npm run audit` раз в месяц и после каждого обновления
   зависимостей.

## Что осталось за рамками

Честный список того, чего нет и почему.

- **Двухфакторная аутентификация.** Для детского продукта избыточна и создаёт
  проблему потерянного доступа у ребёнка. Имеет смысл для аккаунтов
  администраторов, если их станет больше одного.
- **Журнал действий администратора.** Администратор один, и это владелец.
  Понадобится, когда их станет несколько.
- **Шифрование базы.** Файл лежит на диске сервера открытым. Защищается правами
  доступа и шифрованием диска на стороне хостинга.
- **Автоматическое сканирование зависимостей в CI.** `npm run audit` есть, но
  запускается вручную. Стоит повесить на расписание, когда появится сборочный
  конвейер.
- **Ротация секретов.** Смена `JWT_SECRET` разлогинит всех разом. Приемлемо, но
  плавной ротации с двумя действующими ключами нет.
